## Spec

### (a) Missing / partial

* **HC-023(a) SDK calls.** Spec: "a `fetch`/axios/SDK call whose target host
  or port resolves to a sibling service's declared ports or hostname".
  Implemented `findHttpCalls` covers `fetch`/axios/request literals +
  `baseURL/endpoint` config props only; generic SDK-client call shapes (e.g.
  immich's `machine-learning.repository.ts` posts via a typed client,
  supabase studio via api-gw) have no rule.
* **HC-023 env config.** Spec: "(compose service names, `ports:`, env
  config)". Implementation resolves `process.env`/`os.environ` only through
  literal compose `environment:` entries ("only literal compose
  `environment:` values … `.env` files are not read"), so interpolated,
  key-only, `env_file`/`.env` indirection stays silent.
* **HC-026 follow-through.** Spec: "a directory with
  `pyproject.toml`/`uv.lock`/`requirements.txt` is a package whose rooms come
  from its layout (`immich_ml/...`)". Rooms/inventory land, but import-graph
  interior stays JS-shaped and "`huggingface-hub`/`transformers` in pyproject,
  so the model-download flow … draws nothing" remains open by admission.

### (b) Scope creep

* **D21 `serves` edge.** Spec: "Two candidate rules. (a) In-host HTTP call
  inference … (b) Monitoring: `scrape_configs` …". No serve/bundle rule was
  asked; `express.static`/`StaticFiles` → `serves` edge is new behaviour.
* **M3 validity extras.** Spec HC-003: "When `src/` is a package's sole
  dominant segment, promote its expanded rooms directly into the district and
  drop the `Src` wrapper." The diff adds unasked guards in the same function:
  `lib`-child exclusion from `hasInteriorStructure` ("room holding nothing
  but `lib/` plus loose files stays a leaf") and `barrelAwareName` labelling
  of collapsed children.

### (c) Looks implemented but wrong

* **D18 name source.** Spec HC-025: "netlify/vercel yield a site deployable
  (name from the config, entry from `publish`/output dir, build from the
  command)". Implementation names from the owning package (`siteShortName`:
  directory basename), stores `publish` only as attribute, and draws
  `deploys` from runnable/entry-dir room — config name/entry never used.
* **HC-021 placement.** Spec: "it is a component of that deployment (a
  building inside the host), not an artefact of its own." Implementation keeps
  the node in its own package district as `module+bundled`, never parented to
  the host; the "milder `bundled` tag" alternative was allowed but not the
  host-membership the primary direction requires.
* **D19/D20 over-silence.** Spec HC-023(b): "`scrape_configs` job targets
  matching a service's container name or port draw a scrape edge". Resolver
  stays silent on bare-name same-service alternatives and duplicate loopback
  ports ("then it stays silent", "or not at all"), so declared name matches
  the spec would draw are dropped.
